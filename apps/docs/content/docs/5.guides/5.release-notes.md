To generate release notes with AI, give a model the `release-manager` preset and ask it to compare the latest release with the current state of the repository: `getReleaseContext` returns the latest release, the previous one and the comparison between their tags, and the model groups the merged pull requests into notes. This guide does it in one [AI SDK](/integrations/ai-sdk) script that only reads.

## What you'll build

A script you run with a repository name. It prints draft release notes for everything merged since the latest release, grouped into features, fixes and other changes, with one bullet per pull request linking its number. Paste the draft into a GitHub release, or edit it first.

The script never publishes anything. The one write in its preset, `createRelease`, can't run, because nothing in the script answers an approval request.

## Before you start

- Node.js 22 or later.
- A GitHub connector named `github/my-connector` in [Vercel Connect](/auth#create-a-github-connector), with its token pulled into `.env` as `VERCEL_OIDC_TOKEN`. A `GITHUB_TOKEN` with Contents (read) and Pull requests (read) works instead, as shown below.

## 2. Write the script

```ts [scripts/generate-release-notes.ts]
import { connectGithubTools } from '@github-tools/sdk/connect'
import { generateText, stepCountIs } from 'ai'

const [owner, repo] = process.argv.slice(2)
if (!owner || !repo) {
  console.error('Usage: tsx scripts/generate-release-notes.ts <owner> <repo>')
  process.exit(1)
}

const { text } = await generateText({
  model: 'anthropic/claude-opus-5.5',
  tools: connectGithubTools('github/my-connector', {
    preset: 'release-manager',
    context: { owner, repo },
  }),
  stopWhen: stepCountIs(10),
  prompt: `
    Find what changed since the latest release, or since the previous tag if there is no release.
    Draft release notes grouped into "Features", "Fixes" and "Other", one bullet per pull request,
    each linking its number. Do not create the release. Print the draft only.
  `,
})

console.log(text)
```

`connectGithubTools` builds the same tools as `createGithubTools`, with a token minted by the Vercel Connect connector and scoped to the preset. To use `GITHUB_TOKEN` instead, import `createGithubTools` from `@github-tools/sdk` and call it with the same options, without the connector name.

`context` fills in `owner` and `repo` on every call, so the prompt doesn't repeat them ([Context](/context)). `generateText` stops after one step unless you set `stopWhen`, so `stepCountIs(10)` lets the model read, then write the draft.

The `release-manager` [preset](/presets) has `getReleaseContext`, which returns the latest release, the one before it and the comparison between their tags in one call, plus `compareCommits` and `listPullRequests` for the details.

## FAQ

::accordion

:::accordion-item{label="Can the agent publish the release too?"}
Yes, after someone reads the draft. Move the prompt to [`createGithubAgent`](/integrations/ai-sdk#creategithubagent) with the same preset, and answer the `createRelease` approval request once the draft is approved, as in the [quick start](/start/quick-start#_3-approve-the-write).
:::

:::accordion-item{label="Can I run it in CI on every tag?"}
Yes. Run the same script in a GitHub Actions job with `createGithubTools`, the job's `GITHUB_TOKEN`, and your model provider's key as a secret. The script only reads, so nothing waits for approval.
:::

:::accordion-item{label="What if the repository has no releases yet?"}
The prompt tells the model to compare against the previous tag instead. With no tags at all, ask for the changes since a date or a commit.
:::

:::accordion-item{label="How do I change the sections?"}
Edit the prompt. The grouping comes from the instructions, so "Breaking changes", "Features" and "Fixes" work as well as the three above.
:::
