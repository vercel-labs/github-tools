## Overview

An agent with GitHub tools can merge pull requests, close issues and push files. Approval puts a person in front of those actions: when the model calls a write tool, the call stops before it reaches GitHub, and waits until someone says yes or no.

Approval is on by default for all 45 write tools. Read tools never ask. You decide which writes can skip the question, and you can let a fast model approve the routine ones, such as adding a label the user just asked for.

## Configure

Set `requireApproval` where you create the tools or the agent:

```ts [agent.ts]
import { createGithubAgent } from '@github-tools/sdk'

const agent = createGithubAgent({
  model: 'anthropic/claude-opus-5.5',
  preset: 'issue-triage',
  requireApproval: {
    addLabels: false,
    closeIssue: true,
  },
})
```

This agent adds labels without asking and asks before it closes an issue. Every write tool you don't list keeps asking.

| `requireApproval` | What happens |
| --- | --- |
| omitted or `true` | Every write asks |
| `false` | No write asks |
| `'auto'` | A model approves routine writes the user asked for. The rest ask |
| `{ toolName: true \| false \| 'auto' }` | One setting per tool. Unlisted write tools ask |

## Answer a request

When a write needs approval, the agent returns an approval request instead of running the tool. The request names the tool and its input, so you can show the person exactly what will happen:

```ts [triage.ts]
const result = await agent.generate({ messages })

for (const part of result.content) {
  if (part.type === 'tool-approval-request') {
    // part.toolCall.toolName → 'closeIssue'
    // part.toolCall.input → { owner: 'vercel', repo: 'ai', issueNumber: 42 }
  }
}
```

Answer with the request's `approvalId` and `approved: true` or `false`, then call the agent again. The [quick start](/start/quick-start#_3-approve-the-write) shows the whole loop. In a chat UI built with `useChat`, the request arrives as a tool part in the `approval-requested` state, and a button answers it; see [AI SDK](/integrations/ai-sdk#approval-in-a-chat-ui).

## Skip approval in automation

Use `requireApproval: false` when no person is there to answer, and something else reviews the result. A CI job that only opens pull requests is a good fit: the pull request is the review.

Keep the token narrow when you turn approval off. A token without Contents (write) can't push, whatever the model decides. See [Auth](/auth#permissions-per-preset).

## Let a model decide

With `'auto'`, a fast decision model reads each write before it runs and answers two questions: how bad would this be if it were wrong, and did the user ask for this exact action? The write runs only when the risk is low and the request is clear. Otherwise the person is asked as usual.

```ts [agent.ts]
const agent = createGithubAgent({
  model: 'anthropic/claude-opus-5.5',
  preset: 'issue-triage',
  requireApproval: 'auto',
})
```

This protects against instructions hidden in GitHub content. If an issue body tells the agent to post a comment, the user never asked for that comment, so it waits for a person.

`'auto'` covers 14 low-risk tools: labels, assignees, reactions, comments, review replies, reviewer requests and notification reads. Merges, file changes, workflow runs, releases and deletions always ask.

When the agent asks, the request says why, for example "Visible but reversible (risk 0.5 of 2), 1% likely you asked for it". When a write runs without asking, the conversation records it as an automatic approval with its reason.

### Adjust the thresholds

| `evaluation` option | Default | What it does |
| --- | --- | --- |
| `maxRisk` | `1` | Highest risk that runs without asking: `0` negligible, `1` visible but reversible, `2` hard to undo |
| `minIntent` | `0.6` | Lowest likelihood that the user asked for this exact action |
| `model` | `typesafe-ai/jev-1.14.0` | The decision model, called through [AI Gateway](https://vercel.com/docs/ai-gateway) |

## Sign approvals

A chat app sends the whole conversation back to your server on every request, approvals included. Someone could send a forged message that approves a merge nobody saw. Signing stops that:

```ts [agent.ts]
const agent = createGithubAgent({
  model: 'anthropic/claude-opus-5.5',
  experimental_toolApprovalSecret: process.env.TOOL_APPROVAL_SECRET,
})
```

Generate the secret with `openssl rand -base64 32` and use the same value on every server instance. A forged or edited approval is rejected before the tool runs.

## FAQ

### Can a tool ask only the first time?

On eve, yes: set the tool to `'once'`, and it asks once per session. eve also accepts a function of the tool input, for example to ask only outside your own organization. See [eve](/integrations/eve#approval).

### Does approval work in a durable workflow?

Yes. The workflow pauses until someone answers, even hours later, and resumes after a restart. `'auto'` isn't available there. See [Vercel Workflow](/integrations/workflow#approval).

### Does it work with TanStack AI?

Yes. `true` and `false` use TanStack's own approval. `'auto'` needs the GitHub approval middleware. See [TanStack AI](/integrations/tanstack-ai#approval).

### Do I need to sign approvals on eve?

No. eve keeps pending approvals on the server, so the client can't forge one.

### Can I make `'auto'` approve a tool outside the 14?

Yes, by setting that tool to `'auto'` in the per-tool form. The decision model then decides alone whether it runs, so only do this for writes that are cheap to undo.

### What if the decision model is unavailable?

The write asks, as if `'auto'` were `true`. The agent keeps running and logs a `github_tools.EVALUATION_FAILED` warning. This happens when the model isn't enabled for your AI Gateway project, or the team is out of credits.

### Which versions do I need?

`'auto'` needs `ai` 7.0.105 or later, and signing needs `ai` 7.0.36 or later.

### What if `overrides` also sets `needsApproval`?

The value in [`overrides`](/tools#overrides) wins.
