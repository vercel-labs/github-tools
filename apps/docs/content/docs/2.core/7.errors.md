## Overview

GitHub's errors often point at the wrong cause. It answers 404 for a private repository the token can't see, and an expired Vercel OIDC token surfaces as a bare "Not authorized". A model reads both as "the repository is private" or "permissions are missing", and reports the wrong cause.

The SDK turns each failure it can classify into an error with a stable code, the real cause and a fix. That's what the model receives, so it can correct its input or tell the user what to change. Your code gets the same fields to log or act on.

## What the model sees

Each error is an [evlog](https://evlog.dev) error with a code, a `why` and a `fix`:

```json
{
  "name": "EvlogError",
  "message": "GitHub resource not found (404): Not Found",
  "status": 404,
  "data": {
    "code": "github_tools.NOT_FOUND",
    "why": "Either the resource does not exist, or the token cannot see it — GitHub deliberately returns 404 instead of 403 for private resources the token has no access to.",
    "fix": "Check the owner/repo/number input first. If it is correct, the token lacks access: grant the repository to the PAT or App installation, or use a Connect subject that has access.",
    "link": "https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource"
  }
}
```

`link` points to the page that explains the cause, so the model or a person can read further.

| Integration | A failed call |
| --- | --- |
| [AI SDK](/integrations/ai-sdk) | Becomes a `tool-error` part, and the model gets the serialized error above on its next step. In UI messages, the part's `errorText` is the `message` |
| [eve](/integrations/eve) | Returns `{ error: { code, message, why, fix, link } }` as the tool result |

A failing tool doesn't stop `generateText` or `streamText`: the model reads the error and can correct its input or explain the cause.

## Look up a code

Every code starts with `github_tools.`, as in `github_tools.NOT_FOUND`.

### Auth and Vercel Connect

| Code | When |
| --- | --- |
| `TOKEN_REQUIRED` | No token, token function result or `GITHUB_TOKEN` was available. See [Auth](/auth) |
| `OIDC_TOKEN_EXPIRED` | `VERCEL_OIDC_TOKEN` has expired. Thrown before any request, with the expiry time. Run `vercel env pull` |
| `CONNECT_NOT_AUTHORIZED` | Connect refused the process's identity (403). The request never reached GitHub, so this isn't a GitHub permission problem |
| `CONNECT_USER_NOT_CONNECTED` | A [user token](/auth#per-user-tokens) was requested for someone who hasn't connected GitHub |
| `CONNECT_INSTALLATION_REQUIRED` | The connector's GitHub App isn't installed on the target account, named in the message |
| `SUBJECT_CONTEXT_REQUIRED` | An eve `connect` or `connect.subject` function ran outside a tool call |

### Decision model and agent setup

| Code | When |
| --- | --- |
| `EVALUATION_UNAVAILABLE` | `'auto'` was set but the installed `ai` is older than 7.0.105. Thrown when the tools or agent are created |
| `EVALUATION_FAILED` | The [decision model](/approval#let-a-model-decide) call failed. Logged as a warning, not thrown: approval asks, and `preset: 'auto'` uses `repo-explorer` |
| `SESSION_SCOPE_NEEDS_TOOL_SELECTION` | `createGithubAgent` got `scope: 'session'` with `selection: 'presets'`. See [Presets](/presets#route-to-presets-instead) |
| `DURABLE_GENERATE_UNAVAILABLE` | `createDurableGithubAgent(...).generate()` needs `@ai-sdk/workflow` 2.0.59 or later. Use `.stream()` or upgrade |

### GitHub API

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | The token is invalid, expired or revoked |
| `FORBIDDEN` | 403 | A missing permission, SAML enforcement, or a gist or notification tool called with an installation token |
| `RATE_LIMITED` | 403, 429 | The rate limit is used up. The message has the remaining count and the reset time |
| `NOT_FOUND` | 404 | The resource doesn't exist, or the token can't see it |
| `VALIDATION_FAILED` | 422 | GitHub refused well-formed input, such as a duplicate or an unknown ref. GitHub's message names the field |

## Handle a code

To react to a failure in your own code, such as backing off on a rate limit, find the failed calls in the steps. `parseError` from evlog reads the fields back from any of these errors:

```ts [report.ts]
import { githubToolsErrors } from '@github-tools/sdk'
import { generateText } from 'ai'
import { parseError } from 'evlog'

const result = await generateText({ model, tools, prompt })

for (const part of result.steps.flatMap(step => step.content)) {
  if (part.type !== 'tool-error') continue
  const { code, why, fix } = parseError(part.error)
  if (code === githubToolsErrors.RATE_LIMITED.code) {
    // back off until the reset time in the message
  }
}
```

## Fail the same way in your own tools

When you write custom tools next to these, each entry of `githubToolsErrors` also builds the error, so your tools fail with the same shape:

```ts
throw githubToolsErrors.NOT_FOUND({ detail: 'No such workflow' })
```

## FAQ

### Do setup errors reach the model?

No. Errors from your own setup, such as `TOKEN_REQUIRED` from `createGithubTools()`, throw from your code as usual.

### Does the model see the request URL or GitHub's raw error?

No. They stay on the error, as `internal` and `cause`, and are never sent to the model.

### What about statuses without a code, such as 5xx?

They pass through as Octokit's own error.
