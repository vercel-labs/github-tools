## Overview

Commits made by a GitHub tools agent, when it edits files or merges a pull request, come from the token's owner by default: the user behind a personal token, or the App behind an installation token.

::commit-attribution
::

You can credit someone else as co-author, which is the usual way to mark a commit as made with an agent, or set a different author and committer. Which token you use also decides whether GitHub shows the commits as verified.

## Configure

Set the commit options where you create the tools or the agent:

```ts [tools.ts]
import { createGithubTools } from '@github-tools/sdk'

const tools = createGithubTools({
  preset: 'pr-author',
  coAuthors: [
    { name: 'my-bot[bot]', email: '12345+my-bot[bot]@users.noreply.github.com' },
  ],
})
```

| Option | Default | What it sets |
| --- | --- | --- |
| `author` | The token's owner | Who wrote the change, as `{ name, email }` |
| `committer` | The token's owner | Who applied it, as `{ name, email }` |
| `coAuthors` | None | `Co-authored-by` trailers added to every commit message |

The model can't change these options: they're fixed for the tool set, not passed per call.

### Which tools commit

| Tool | `author`, `committer` | `coAuthors` |
| --- | --- | --- |
| `createOrUpdateFile` | Yes | Yes |
| `editFiles` | Yes | Yes |
| `mergePullRequest` | No | Yes, in the merge commit message |
| `enablePullRequestAutoMerge` | No | Yes, in the commit made when it merges |

## Credit a co-author

`coAuthors` keeps the token's owner as the author and credits someone else in the commit message. Every commit message ends with a trailer, which GitHub shows as a second avatar on the commit:

```txt [commit message]
Update README.md

Co-authored-by: my-bot[bot] <12345+my-bot[bot]@users.noreply.github.com>
```

`coAuthors` works whether or not the commit is signed. GitHub's docs cover [commits with several authors](https://docs.github.com/en/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/creating-a-commit-with-multiple-authors).

## Get verified commits

GitHub shows a commit as **Verified** when it's signed. `createOrUpdateFile` and `editFiles` first try GitHub's `createCommitOnBranch` GraphQL mutation, which writes every change as one commit. GitHub signs that commit only when the token acts as a GitHub App:

| Token | Verified |
| --- | --- |
| GitHub App installation token, including a [Vercel Connect](/auth#vercel-connect) one | Yes |
| `GITHUB_TOKEN` in GitHub Actions | Yes |
| Personal access token | No |
| User OAuth token, including a Connect [user token](/auth#per-user-tokens) | No |

Use an App token when the branch's protection rules require signed commits. GitHub's docs cover [signature verification](https://docs.github.com/en/authentication/managing-commit-signature-verification/about-commit-signature-verification).

## Set the author or committer

`author` and `committer` make the commits come from another identity than the token's owner. Setting either one skips the signed path, because the mutation doesn't accept custom identities. The tools then use the REST contents API: the commit isn't signed, and `editFiles` makes one commit per file.

## FAQ

### Why isn't a commit made with a user token verified?

GitHub signs commits only for bots, because it doesn't hold the user's signing key. A commit made with a user token is valid but not verified.

### What if GitHub refuses the signed commit?

The tools fall back to the REST contents API and log a `Signed commit failed` warning. The commit is then unsigned.

### What if the branch moves while the agent commits?

If the branch moves between reading it and committing, the mutation fails instead of falling back, so the agent doesn't overwrite a change it hasn't seen.

### Where can I set these options?

`createGithubTools`, `createGithubAgent`, `createDurableGithubAgent`, TanStack AI and the [eve extension](/integrations/eve) all take them. With [single tool factories](/tools#pick-single-tools), pass them next to `needsApproval`, for example `editFiles(token, { coAuthors })`.
