`createGithubTools()` returns 91 GitHub tools, 46 read and 45 write, grouped below by GitHub domain. The 45 marked **Write** ask for [approval](/approval) by default. [Tools](/tools) covers output shape, paging and overrides, and [Presets](/presets) lists which tools each job gets.

## Repository

| Tool | Write | What it does |
| --- | --- | --- |
| `getRepository` |  | Get information about a GitHub repository including description, stars, forks, language, and default branch. |
| `listBranches` |  | List branches in a GitHub repository. |
| `getFileContent` |  | Get the content of a file from a GitHub repository. Reads a line range with `startLine`/`endLine` or `maxLines`. |
| `getRepositoryTree` |  | List the file and directory structure of a repository at a given ref. Takes a `path` prefix. |
| `createBranch` | Yes | Create a new branch in a GitHub repository from an existing branch or commit SHA. |
| `deleteBranch` | Yes | Delete a branch from a GitHub repository permanently. |
| `forkRepository` | Yes | Fork a GitHub repository to the authenticated user account or a specified organization. |
| `createRepository` | Yes | Create a new GitHub repository for the authenticated user or a specified organization. |
| `createOrUpdateFile` | Yes | Create or update a file in a GitHub repository. Provide the SHA when updating an existing file. |
| `editFiles` | Yes | Edit files and commit them in one call: replace exact text in a file without reading or resending the whole file, or write whole files, on a new or existing branch, and optionally open a pull request. Replaces `createBranch`, `createOrUpdateFile` and `createPullRequest` chains. |
| `getBranchRules` |  | List what protects a branch: required status checks, required reviews, and the other ruleset and branch-protection rules. Use it to explain why a pull request cannot merge yet. |

## Pull requests

| Tool | Write | What it does |
| --- | --- | --- |
| `listPullRequests` |  | List pull requests for a GitHub repository. |
| `getPullRequest` |  | Get detailed information about a specific pull request. Body is truncated by default. Set `detail: 'full'` for the complete description. |
| `createPullRequest` | Yes | Create a new pull request in a GitHub repository. |
| `mergePullRequest` | Yes | Merge a pull request. |
| `updatePullRequest` | Yes | Update a pull request: title, body, state, base branch, or draft status. Draft toggling uses the GraphQL API. |
| `addPullRequestComment` | Yes | Add a comment to a pull request. |
| `updatePullRequestComment` | Yes | Update the body of a comment on a pull request. |
| `deletePullRequestComment` | Yes | Delete a comment from a pull request permanently. |
| `listPullRequestFiles` |  | List files changed in a pull request with status and stats. Patches are omitted unless `includePatch` is true, optionally limited by `filenames`. |
| `listPullRequestReviews` |  | List reviews on a pull request (approvals, change requests, and comments). |
| `createPullRequestReview` | Yes | Submit a pull request review: approve, request changes, or comment with optional inline comments on a line or a range of lines, including suggested changes the author can apply. |
| `listPullRequestReviewThreads` |  | List review threads on a pull request with their comments, resolution state, and the IDs to reply (`commentId`) or resolve (`threadId`). Unresolved threads only by default (GraphQL API). |
| `replyToReviewComment` | Yes | Reply to a pull request review comment, adding a message to its review thread. |
| `resolveReviewThread` | Yes | Mark a pull request review thread as resolved. |
| `requestReviewers` | Yes | Request reviews from users or teams on a pull request. |
| `enablePullRequestAutoMerge` | Yes | Merge a pull request automatically once its required checks and reviews pass. The repository must allow auto-merge; a pull request that can already merge needs `mergePullRequest`. |
| `disablePullRequestAutoMerge` | Yes | Cancel a pending auto-merge, so the pull request stays open when its checks pass. |

## Commits

| Tool | Write | What it does |
| --- | --- | --- |
| `listCommits` |  | List commits for a GitHub repository. Filters by `path`, `author`, `since` or `until`. |
| `getCommit` |  | Get detailed information about a specific commit, including the list of files changed with additions and deletions. Patches are omitted unless `includePatch` is true. |
| `getBlame` |  | Line-level git blame for a file at a commit-like ref (branch, tag, or SHA). Returns contiguous ranges mapping lines to the commits that last modified them, to see who introduced a line and when (GraphQL API). |
| `compareCommits` |  | Compare two branches, tags, or commits: ahead/behind counts, ahead/behind counts, the commits in between, and the files that differ. Patches are omitted unless `includePatch` is true. |

## Security alerts

| Tool | Write | What it does |
| --- | --- | --- |
| `listCodeScanningAlerts` |  | List code scanning alerts (CodeQL and other analysis tools) for a repository, newest first, with the rule, its severity, and the file and line of the latest instance. Needs code scanning set up on the repository. |
| `listDependabotAlerts` |  | List Dependabot alerts for vulnerable dependencies, newest first, with the package, the advisory (GHSA and CVE IDs, severity, summary), the vulnerable range and the first patched version. |
| `listSecretScanningAlerts` |  | List secret scanning alerts for credentials committed to a repository, newest first, with the secret type, whether the secret is still valid, and whether push protection was bypassed. The secret itself is never returned. |

## Context tools

| Tool | Write | What it does |
| --- | --- | --- |
| `getPullRequestContext` |  | Fetch pull request details plus files, reviews, and optional CI checks and linked issues in one call, instead of separate `getPullRequest`, `listPullRequestFiles` and `listPullRequestReviews` calls. |
| `getIssueContext` |  | Fetch an issue plus available label names and recent comments in one call, for triage. |
| `getReleaseContext` |  | Fetch a release (latest, by ID, or by tag) plus the release before it and the comparison between their tags in one call, for preparing or reviewing a release. |
| `getCiFailureContext` |  | Diagnose CI failures in one call, for a ref or one workflow run: failing checks and statuses (for a ref), recent failed runs, failed jobs and steps, and the end of each failed job's log. |
