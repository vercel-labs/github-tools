`@github-tools/sdk` publishes eight entry points, and `@github-tools/eve-extension` one more. Each section lists what an entry point exports; the guides linked from each one explain when to use it.

| Entry point | For | Peer packages |
| --- | --- | --- |
| [`@github-tools/sdk`](#github-toolssdk) | AI SDK tools and agent | `ai`, `zod` |
| [`@github-tools/sdk/workflow`](#github-toolssdkworkflow) | Durable agent | `ai`, `zod`, `workflow`, `@ai-sdk/workflow` |
| [`@github-tools/sdk/connect`](#github-toolssdkconnect) | Tokens from Vercel Connect | `ai`, `zod`, `@vercel/connect` |
| [`@github-tools/sdk/tanstack`](#github-toolssdktanstack) | TanStack AI tools and agent | `@tanstack/ai`, `zod`, and `@tanstack/ai-vercel-gateway` for the default decision adapter |
| [`@github-tools/sdk/tanstack/interrupts`](#github-toolssdktanstackinterrupts) | The approval interrupt, safe in the browser | `@tanstack/ai`, `zod` |
| [`@github-tools/sdk/eve-runtime`](#github-toolssdkeve-runtime) | Building blocks of the eve extension | `eve`, `ai`, `zod` |
| [`@github-tools/eve-extension`](#github-toolseve-extension) | GitHub tools in an eve agent | `eve` |
| `@github-tools/sdk/eve`, `@github-tools/sdk/connect/eve` | Deprecated. See [Upgrade](/reference/upgrade) | `eve` |

## `@github-tools/sdk`

### `createGithubTools`

```ts
function createGithubTools(options?: GithubToolsOptions): ToolSet
```

Returns an AI SDK `ToolSet` keyed by tool name, typed to the preset you pass. With no `preset`, it holds all 97 [tools](/reference/tools).

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `token` | `GithubTokenInput` | `process.env.GITHUB_TOKEN` | A token, or an async provider called before every tool call. A missing string token throws `TOKEN_REQUIRED` when the tools are created |
| `preset` | `GithubToolPreset \| GithubToolPreset[]` | all tools | Keep only the tools of one or more [presets](/presets) |
| `requireApproval` | `ApprovalConfig` | `true` | Which writes ask first. See [Approval](/approval#configure) |
| `evaluation` | `GithubEvaluationOptions` | | Tuning for `'auto'`. See [below](#githubevaluationoptions) |
| `context` | `GithubToolsContext` | | Default `owner`, `repo`, `pullNumber`, `issueNumber` and `ref`. See [Context](/context) |
| `overrides` | `Partial<Record<GithubToolName, ToolOverrides>>` | | Per-tool `description`, `title`, `needsApproval`, `strict`, `providerOptions`, `toModelOutput`, `onInputStart`, `onInputDelta`, `onInputAvailable`. `execute` and the schemas can't be overridden |
| `author` | `CommitIdentity` | the token's user | Commit author for `createOrUpdateFile` and `editFiles` |
| `committer` | `CommitIdentity` | the token's user | Committer for the same tools |
| `coAuthors` | `CommitIdentity[]` | | `Co-authored-by` trailers on `createOrUpdateFile`, `editFiles`, `mergePullRequest` and `enablePullRequestAutoMerge`. See [Commits](/commits) |
| `guardrails` | `GithubGuardrails` | `{ secrets: 'block' }` | Repositories and branches any call may act on, whoever approves it. A blocked call throws `GUARDRAIL_BLOCKED`. See [Guardrails](/approval#guardrails) |
| `dryRun` | `boolean` | `false` | Shadow mode: reads run, and writes return a `GithubDryRunResult` without reaching GitHub or asking anyone. See [Shadow mode](/approval#shadow-mode) |

Object results carry a `rateLimit` field (`GithubRateLimit`) from the last GitHub response. `createGithubTools` strips it from what the model sees; your hooks and UI still get it.

### `createGithubAgent`

```ts
function createGithubAgent(options: CreateGithubAgentOptions): ToolLoopAgent
```

Returns an AI SDK `ToolLoopAgent` with the tools, the preset's system prompt and call-level approval. It takes every `createGithubTools` option, every `ToolLoopAgent` setting except `tools` and `instructions` (such as `stopWhen`, `prepareCall` or `experimental_toolApprovalSecret`), and these:

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `model` | `LanguageModel` | required | A Gateway model ID or a model instance |
| `preset` | `GithubToolPreset \| GithubToolPreset[] \| 'auto'` | all tools | `'auto'` lets the decision model pick the tools. See [Presets](/presets). Needs `ai` 7.0.105 or later |
| `instructions` | `string` | the preset's prompt | Replaces the system prompt. `context` is still appended |
| `additionalInstructions` | `string` | | Appended to the preset's prompt. Ignored when `instructions` is set |

With `requireApproval: 'auto'`, an approval request carries the decision model's reason, and a call it let through is recorded with `isAutomatic: true`. A write that `guardrails` block is denied with the reason, before anyone is asked. A tool from outside the GitHub catalog, for example one added in `prepareCall`, keeps its own `needsApproval`. Passing your own `toolApproval` replaces this policy.

### `GithubEvaluationOptions`

Tunes `requireApproval: 'auto'` and `preset: 'auto'`. Every field is optional.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `model` | `Experimental_EvaluationModel` | `'typesafe-ai/jev-1.14.0'` | Decision model: a Gateway ID or an instance |
| `providerOptions` | `Record<string, Record<string, JSONValue>>` | | Passed to every decision call |
| `maxRisk` | `number` | `1` | Highest risk that runs without asking, from `0` to `2` |
| `minIntent` | `number` | `0.6` | Lowest probability that the user asked for this call |
| `selection` | `'tools' \| 'presets'` | `'tools'` | What `preset: 'auto'` picks |
| `scope` | `'session' \| 'turn'` | `'session'` (`'turn'` with `selection: 'presets'`) | Pick once per conversation, or again for each request |
| `minToolProbability` | `number` | `0.5` | Lowest probability for a tool to be listed |
| `maxTools` | `number` | `8` | Most tools listed beyond the core read tools |
| `minPresetProbability` | `number` | `0.7` | Lowest probability for a preset to be picked |
| `maxPresets` | `number` | `2` | Most presets combined |
| `store` | `{ get, set }` | in memory | Keeps `preset: 'auto'` picks across processes |

`createGithubAgent` throws `SESSION_SCOPE_NEEDS_TOOL_SELECTION` for `scope: 'session'` with `selection: 'presets'`.

### Tool factories

Each of the 97 tools is also exported as a factory, for building a tool set by hand:

```ts
getRepository(token: GithubTokenInput): GithubTool
createIssue(token: GithubTokenInput, options?: ToolOptions): GithubTool
createOrUpdateFile(token: GithubTokenInput, options?: CommitToolOptions): GithubTool
mergePullRequest(token: GithubTokenInput, options?: ToolOptions & { coAuthors?: CommitIdentity[] }): GithubTool
```

Read factories take only the token. Write factories take `needsApproval` (a boolean or an AI SDK approval function), `true` by default. `CommitToolOptions` adds `author`, `committer` and `coAuthors`. `editFiles` takes the same options as `createOrUpdateFile`, and `enablePullRequestAutoMerge` the same as `mergePullRequest`. `mergePullRequest` and `enablePullRequestAutoMerge` also take `branches`, and `updatePullRequestBranch` takes `guardrails`, to check the pull request's branches. Factories don't apply `context`, `guardrails` or `dryRun`, or strip `rateLimit`; `createGithubTools` does.

### `withGithubGuardrails`

```ts
function withGithubGuardrails(token: GithubTokenInput | undefined, guardrails: GithubGuardrails | undefined): (call?: GithubTokenCall) => Promise<string>
```

Wraps a token so every call it resolves for is checked against `guardrails` first, including the default credential check. A blocked call throws `GUARDRAIL_BLOCKED` before any request reaches GitHub. Use it with the factories; `createGithubTools({ guardrails })` applies it for you. See [Guardrails](/approval#guardrails).

### `resolveGithubToken`

```ts
function resolveGithubToken(token?: GithubTokenInput, call?: GithubTokenCall): Promise<string>
```

Resolves a token string, a provider, or `GITHUB_TOKEN` to a string. Throws `TOKEN_REQUIRED` when none is available.

### `createOctokit`

```ts
function createOctokit(token: string): Octokit
```

Returns an [`octokit`](https://github.com/octokit/octokit.js) client that sends the GitHub API version header the tools use and turns failures into `githubToolsErrors`. Use it for calls your code makes without a model:

```ts
const octokit = createOctokit(await resolveGithubToken())
const { data } = await octokit.rest.repos.get({ owner: 'vercel-labs', repo: 'github-tools' })
```

### `githubToolsErrors`

The [evlog](https://evlog.dev) error catalog behind every `github_tools.*` error, each with `why` and `fix`. [Errors](/errors) lists the codes.

### `selectTools` and `selectPresets`

```ts
function selectTools(messages: ModelMessage[], options?: GithubEvaluationOptions, abortSignal?: AbortSignal): Promise<GithubToolName[]>
function selectPresets(messages: ModelMessage[], options?: GithubEvaluationOptions, abortSignal?: AbortSignal): Promise<GithubToolPreset[]>
```

The routing behind `preset: 'auto'`, for your own `prepareStep` or `activeTools`. `selectTools` returns the core read tools plus up to `maxTools` others; `selectPresets` returns up to `maxPresets` presets, never `maintainer`. When the decision call fails, both fall back to `repo-explorer` and log `EVALUATION_FAILED`.

### Constants

| Export | Value |
| --- | --- |
| `PRESET_TOOLS` | `Record<GithubToolPreset, readonly GithubToolName[]>`: the tools of each preset |
| `GITHUB_TOOL_NAMES` | `{ [name]: name }` for all 97 tools. `Object.keys()` gives the list |
| `GITHUB_WRITE_TOOLS` | `{ [name]: name }` for the 48 write tools |
| `CORE_READ_TOOLS` | `['getRepository', 'getFileContent', 'getRepositoryTree', 'searchCode', 'listCommits']`, in every preset |
| `AUTO_APPROVAL_TOOLS` | The 14 write tools `requireApproval: 'auto'` evaluates |
| `DEFAULT_EVALUATION_MODEL` | `'typesafe-ai/jev-1.14.0'` |
| `CALL_GITHUB_TOOL` | `'callGithubTool'`, the tool `preset: 'auto'` adds to reach unlisted tools |

### Types

| Type | Shape |
| --- | --- |
| `GithubTokenInput` | `string \| ((call?: GithubTokenCall) => Promise<string>)` |
| `GithubTokenCall` | `{ toolName, input, owner?, repo? }`: the call a provider mints for. `owner` and `repo` are unset for search, gist and notification tools |
| `ApprovalConfig` | `boolean \| 'auto' \| Partial<Record<GithubWriteToolName, boolean \| 'auto'>>`. `StaticApprovalConfig` is the same without `'auto'` |
| `GithubToolsContext` | `{ owner?, repo?, pullNumber?, issueNumber?, ref? }` |
| `CommitIdentity` | `{ name: string, email: string }` |
| `GithubToolPreset` | One of the ten [preset](/presets) names |
| `GithubGuardrails` | `{ repositories?: string[], branches?: string[], secrets?: 'block' \| 'allow' }`. `repositories` takes `owner/repo` or `owner/*`, `branches` takes names or patterns such as `agent/*` |
| `GithubDryRunResult` | `{ dryRun: true, tool, input, approval?, message }`: what a write returns under `dryRun` |
| `GithubDryRunApproval` | `{ required: boolean, reason? }`: whether approval would have asked a person, with the decision model's verdict under `'auto'` |

Also exported: `GithubToolName`, `GithubWriteToolName`, `ToolApprovalMode`, `ToolOverrides`, `ToolOptions`, `CommitToolOptions`, `GithubTool`, `GithubTools`, `GithubToolsOptions`, `CreateGithubAgentOptions`, `AllGithubTools`, `GithubToolsForPreset`, `PickGithubTools`, `PresetToolName`, `CombinedPresetToolNames`, `GithubRateLimit`, `Octokit`.

## `@github-tools/sdk/workflow`

### `createDurableGithubAgent`

```ts
function createDurableGithubAgent(options: CreateDurableGithubAgentOptions): DurableGithubAgent
```

Returns an agent built on `WorkflowAgent`. Call it inside a `"use workflow"` function: each model call and tool call runs as a workflow step, and a write that needs approval pauses the run. It takes every `WorkflowAgent` option except `tools` and `instructions` (such as `stopWhen` or `experimental_toolApprovalSecret`), and `model`, `token`, `preset`, `overrides`, `context`, `instructions`, `additionalInstructions`, `author`, `committer`, `coAuthors`, `guardrails` and `dryRun` as above, with two differences:

| Option | Difference |
| --- | --- |
| `preset` | No `'auto'` |
| `requireApproval` | `StaticApprovalConfig`: no `'auto'`, because the decision call can't run inside a workflow function |

| Member | What it does |
| --- | --- |
| `stream({ messages, writable })` | Writes `ModelCallStreamPart`s to the writable, for chat UIs |
| `generate(options)` | Returns the finished result, for bots and jobs. Needs `@ai-sdk/workflow` 2.0.59 or later, otherwise throws `DURABLE_GENERATE_UNAVAILABLE`. Stops after 20 steps unless `stopWhen` says otherwise |
| `tools` | The agent's tool set |

The entry point also re-exports `createGithubTools`, `createGithubAgent`, `resolveGithubToken`, the constants and the types above. See [Vercel Workflow](/integrations/workflow).

## `@github-tools/sdk/connect`

### `connectGithubTools`

```ts
function connectGithubTools(connector: GithubConnectorInput, options?: ConnectGithubToolsOptions): ToolSet
```

`createGithubTools` with a token from a Vercel Connect connector. It takes every `createGithubTools` option except `token`, plus `connect`, and scopes the token to `preset`.

### `connectGithubToken`

```ts
function connectGithubToken(connector: GithubConnectorInput, options?: ConnectGithubTokenOptions): GithubTokenInput
```

A token provider for any `token` option. It mints a token on each call; Connect caches it per connector and parameters.

| Option | Type | Meaning |
| --- | --- | --- |
| `preset` | `GithubToolPreset \| GithubToolPreset[]` | Scopes the token to these presets. Pass the same presets as the tools |
| `include`, `exclude` | `GithubToolName[]` | Scopes the token to an exact tool selection instead |
| `params` | `GithubConnectParams \| (call?) => GithubConnectParams` | Token parameters, static or per call |
| `connectOptions` | `ConnectOptions` | Passed to `@vercel/connect` |

| Type | Shape |
| --- | --- |
| `GithubConnectorInput` | `string \| (() => string \| Promise<string>)`: a connector name, or a resolver called on every token request |
| `GithubConnectParams` | Connect's `ConnectTokenParams` with `subject` (default `{ type: 'app' }`, or `{ type: 'user', id }` for [per-user tokens](/auth#per-user-tokens)) and `repositories` to limit the token. `scopes` replaces the preset's scopes |

An app token targets the installation that owns the call's repository unless `installationId`, `authorizationDetails` or `repositories` pins one. See [Auth](/auth#vercel-connect).

### Scope helpers

| Export | Returns |
| --- | --- |
| `connectGithubScopesForPreset(preset?)` | Scopes for one or more presets, or every tool's scopes without one |
| `connectGithubScopesForTools(names)` | Scopes covering exactly these tools, always with `metadata:read` |
| `connectGithubScopesForSelection({ preset?, include?, exclude? })` | The scopes `connectGithubToken` requests when `params.scopes` is unset |
| `PRESET_CONNECT_SCOPES`, `TOOL_CONNECT_SCOPES` | The scopes per preset and per tool. Gist and notification tools have none, because installation tokens can't call those APIs |
| `resolveGithubConnector(connector)` | The connector name a `GithubConnectorInput` resolves to |

## `@github-tools/sdk/tanstack`

Native [TanStack AI](/integrations/tanstack-ai) server tools, with the same names and inputs.

### `createGithubTools` for TanStack

```ts
function createGithubTools(options?: CreateGithubToolsOptions): GithubTanstackTool[]
```

Returns an array of server tools. Takes `token`, `preset`, `requireApproval`, `context`, `author`, `committer`, `coAuthors`, `guardrails` and `dryRun` as in the AI SDK version, and `overrides` limited to `description` and a boolean `needsApproval`. `true` and `false` approval use TanStack's own approval; `'auto'` needs the middleware below, and without it those writes keep asking.

### `createGithubAgent` for TanStack

```ts
function createGithubAgent(options: CreateGithubAgentOptions): GithubAgent
```

Takes the tool options, every TanStack `chat()` setting such as `adapter` (required) and `modelOptions`, and:

| Option | Meaning |
| --- | --- |
| `preset` | A preset, an array, or `'auto'` to route each new request |
| `instructions`, `additionalInstructions` | As in the AI SDK version |
| `evaluation` | `{ adapter?, maxRisk?, minIntent?, minPresetProbability?, maxPresets? }`. The default adapter is `vercelGatewayDecider('typesafe-ai/jev')` from `@tanstack/ai-vercel-gateway` |
| `middleware` | More TanStack middleware, run after the approval middleware |

`agent.stream({ prompt })` returns TanStack's event stream, including approval interrupts. `agent.generate({ prompt })` returns `Promise<string>` and throws when the run stops for an approval. Both take `messages` instead of `prompt`; the agent keeps no history between calls.

### Other exports

| Export | What it is |
| --- | --- |
| `createGithubApprovalMiddleware({ tools, evaluation? })` | Runs the `'auto'` decision before each write and raises `githubToolApproval` when a person must answer. Pass it the same tools as `chat()`. `createGithubAgent` adds it for you |
| `getRepository(token, options?)` and the 96 other factories | One server tool. `options`: `description`, `needsApproval` (`boolean \| 'auto'`), `context`, `author`, `committer`, `coAuthors` |
| `selectPresets(messages, evaluation?, signal?)` | Preset routing with the TanStack adapter |
| `PRESET_TOOLS`, `GITHUB_TOOL_NAMES`, `GITHUB_WRITE_TOOLS`, `AUTO_APPROVAL_TOOLS`, `DEFAULT_EVALUATION_MODEL` | As above |

## `@github-tools/sdk/tanstack/interrupts`

`githubToolApproval` is the interrupt definition (`id: 'github-tools.approval'`) to register on both the server and the client. Its payload is `{ toolCallId, toolName, input }` and its response `{ approved: boolean }`. An answer applies only to that call with that input.

## `@github-tools/sdk/eve-runtime`

The building blocks `@github-tools/eve-extension` is made of. Mount the extension instead unless you're building your own eve integration.

| Export | What it does |
| --- | --- |
| `createEveGithubToolsDynamic(options)` | A `defineDynamic` tool set from `EveGithubToolsOptions` |
| `buildEveToolMap(options)`, `buildEveToolDefinition(...)` | eve `defineTool` values for the selected tools |
| `listEveToolDescriptors(options)` | Tool descriptors without `execute` |
| `listResolvedEveToolNames({ preset?, include?, exclude? })` | The tool names a selection resolves to |
| `executeGithubEveTool(name, input, options)` | Runs one tool by name |
| `formatGithubEveToolOutput`, `hasGithubEveToolModelOutput` | The model-facing output of a tool's result |
| `mapEveApprovalValue`, `resolveEveApproval`, `resolveEveToolApproval`, `isEveApprovalDisabled` | Map `true`, `'once'`, `'never'` and predicates to eve approval policies |
| `needsAutoApproval`, `evaluateTools`, `evaluatePresets`, `selectTools`, `selectPresets`, `fallbackTools`, `fallbackPresets`, `latestUserText` | The decision model calls behind the `'auto'` options |
| `autoApprovalDecision` | Asks the decision model about one GitHub write and returns `{ ask, reason }`, the verdict the extension adds to approval prompts |
| `githubGuardrailViolation(name, input, { context, guardrails })` | Why `guardrails` block a call after `context` defaults, or `undefined` |
| `resolveToolGuidance(options)` | The tool-usage instructions without the preset's "You are" opener |
| `withGithubCallerAccess(token, { login, repository? })` | Wraps a token so each call is first checked against what `login` may do on the call's target repository. A refused call throws `CALLER_FORBIDDEN` |
| `githubCallerViolation(call, caller, token)` | Why a person's role refuses a call, or `undefined` |
| `githubRoleRank({ permission, roleName })`, `GITHUB_ROLES` | GitHub's repository roles in order, and the rank of a collaborator permission answer |

It also exports `resolveGithubToken`, `githubToolsErrors`, the constants and the types, including `EveGithubToolsOptions`, `EveApprovalValue`, `EveToolOverrides`, `GithubGuardrails` and `GithubDryRunResult`.

## `@github-tools/eve-extension`

```ts
import githubExtension from '@github-tools/eve-extension'

export default githubExtension({ connector: 'github/my-connector', preset: 'code-review' })
```

The default export mounts the tools in an eve agent from a file under `agent/extensions/`. The file name becomes the namespace, so `agent/extensions/github.ts` exposes `github__listPullRequests` and so on. It takes `token`, `connector`, `actAs`, `approvers`, `connect`, `preset` (including `'auto'`), `include`, `exclude`, `context`, `requireApproval` (adding `'once'` and predicates), `evaluation`, `overrides`, `author`, `committer`, `coAuthors`, `guardrails` and `dryRun`; [eve](/integrations/eve) documents each one. Needs Node 24 or later and `eve` as a peer.

`@github-tools/eve-extension/channels` exports `githubChannel`, which is eve's `githubChannel` plus `respondTo` (`'anyone'`, `'triagers'`, `'writers'`, `'maintainers'` or `'admins'`), and the `GithubChannelConfig` and `GithubRespondTo` types. See [Choose who the agent answers](/integrations/eve#choose-who-the-agent-answers).
