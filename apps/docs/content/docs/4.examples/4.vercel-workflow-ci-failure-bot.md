Ask "why did CI fail on #128?" and the agent finds the failing run, reads the failed jobs and the end of their logs, and explains the likely cause before suggesting a fix. Every model call and tool call runs as a workflow step, so a long investigation resumes where it stopped after a timeout or a redeploy.

## Files

```text
server/
├── workflows/
│   └── ci-failure-bot.ts                  # the agent
└── api/
    ├── ci-chat.post.ts                    # starts a run
    └── ci-chat/[runId]/stream.get.ts      # reconnects to a run
```

The workflow holds the whole agent:

```ts [server/workflows/ci-failure-bot.ts]
import { createDurableGithubAgent } from '@github-tools/sdk/workflow'
import { connectGithubToken } from '@github-tools/sdk/connect'
import type { ModelCallStreamPart } from '@ai-sdk/workflow'
import type { ModelMessage } from 'ai'
import { getWritable } from 'workflow'

export async function ciFailureBot(messages: ModelMessage[]) {
  'use workflow'

  const agent = createDurableGithubAgent({
    model: 'anthropic/claude-opus-5.5',
    token: connectGithubToken('github/my-connector', { preset: 'ci-ops' }),
    preset: 'ci-ops',
    additionalInstructions: 'Explain the likely cause of a failure in plain language before suggesting a fix. Do not rerun anything unless asked.',
  })

  await agent.stream({ messages, writable: getWritable<ModelCallStreamPart>() })
}
```

The `ci-ops` [preset](/presets) gives it `getCiFailureContext`, which returns the failing checks, failed runs, failed jobs and steps, and the end of each failed job's log in one call. Its writes, `triggerWorkflow`, `cancelWorkflowRun` and `rerunWorkflowRun`, ask for [approval](/approval), which pauses the run until someone answers. Pass the same `preset` to `connectGithubToken` so the token covers the same permissions.

The route starts a run and streams it back as UI message chunks:

```ts [server/api/ci-chat.post.ts]
import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow'
import { convertToModelMessages, createUIMessageStreamResponse, type UIMessage } from 'ai'
import { start } from 'workflow/api'
import { ciFailureBot } from '../workflows/ci-failure-bot'

export default defineEventHandler(async (event) => {
  // Anyone who can start a run reads CI data with the connector's access.
  await requireUserSession(event)
  const { messages } = await readBody<{ messages: UIMessage[] }>(event)
  const run = await start(ciFailureBot, [await convertToModelMessages(messages)])

  return createUIMessageStreamResponse({
    stream: run.readable.pipeThrough(createModelCallToUIChunkTransform()),
    headers: { 'x-workflow-run-id': run.runId },
  })
})
```

`requireUserSession` comes from [nuxt-auth-utils](https://github.com/atinux/nuxt-auth-utils); use your app's own check elsewhere. The reconnect route reads `getRun(runId).getReadable({ startIndex })` through the same transform, and the client talks to both with `WorkflowChatTransport`. [Vercel Workflow](/integrations/workflow) has both.

## Install

:::code-group
```bash [pnpm]
pnpm add @github-tools/sdk @vercel/connect workflow @ai-sdk/workflow ai zod
```
```bash [npm]
npm install @github-tools/sdk @vercel/connect workflow @ai-sdk/workflow ai zod
```
```bash [yarn]
yarn add @github-tools/sdk @vercel/connect workflow @ai-sdk/workflow ai zod
```
```bash [bun]
bun add @github-tools/sdk @vercel/connect workflow @ai-sdk/workflow ai zod
```
:::

Create a connector named `github/my-connector`, installed on the repositories the bot watches, and pull its token as [Auth](/auth#create-a-github-connector) describes.

## Run it

Start your app's dev server, open the chat, and ask about a failing run, such as "why did the last run on main fail in vercel-labs/github-tools?". The answer streams in while the agent reads the run. `npx workflow web` shows each run and the steps it took.

## Go further

Start the same workflow from a GitHub webhook on `workflow_run` with `conclusion: failure`, so the diagnosis is waiting before anyone asks.
