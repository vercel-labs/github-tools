Mention the bot on an issue and it adds an `eyes` reaction, classifies the issue as a bug, a feature or a question, applies the matching label, and posts a comment with a suggested next step. Replies in the same thread continue the conversation, and each turn runs as a durable workflow step.

## Files

This is the [PR review agent](https://github.com/vercel-labs/github-tools/tree/main/examples/pr-review-agent) with a different workflow and preset. Copy that project and change two files:

```text
server/
├── lib/
│   ├── agent.ts                    # Chat SDK bot: import triageWorkflow instead of reviewWorkflow
│   └── github.ts                   # token and permission check: preset 'issue-triage'
├── routes/webhooks/github.post.ts  # webhook endpoint, unchanged
└── workflows/
    └── triage.ts                   # replaces review.ts
```

`lib/github.ts` mints a token limited to the repository the webhook came from, and only lets people who can write to that repository drive the bot, since every call acts as the GitHub App. Set its preset to `issue-triage`:

```ts [server/lib/github.ts]
export function repositoryToken(owner: string, repo: string) {
  return connectGithubToken(CONNECTOR, { preset: 'issue-triage', params: { repositories: [`${owner}/${repo}`] } })
}
```

The workflow runs one agent turn for the mention, then one per follow-up message:

```ts [server/workflows/triage.ts]
import { createGithubAgent } from '@github-tools/sdk'
import { createHook, getWorkflowMetadata } from 'workflow'
import type { ChatTurnPayload, GitHubContext } from '../lib/agent'
import { repositoryToken } from '../lib/github'

async function runTriageTurn(prompt: string, ctx: GitHubContext) {
  'use step'
  const agent = createGithubAgent({
    model: 'anthropic/claude-opus-5.5',
    token: repositoryToken(ctx.owner, ctx.repo),
    preset: 'issue-triage',
    requireApproval: { addLabels: false, addIssueComment: false },
    context: { owner: ctx.owner, repo: ctx.repo, issueNumber: ctx.issueNumber },
    additionalInstructions: `
      Classify the issue as bug, feature, or question.
      Apply the matching label with addLabels, then post one comment with the
      classification and a one-line suggested next step. Do not close anything.
    `,
  })
  const { text } = await agent.generate({ prompt })
  return text
}

export async function triageWorkflow(prompt: string, ctx: GitHubContext) {
  'use workflow'
  using hook = createHook<ChatTurnPayload>({ token: getWorkflowMetadata().workflowRunId })

  await runTriageTurn(prompt, ctx)
  for await (const event of hook) {
    await runTriageTurn(event.text, ctx)
  }
}
```

Labels and comments run without asking. Every other write in the `issue-triage` [preset](/presets), such as `closeIssue`, still needs [approval](/approval), and since nothing answers approvals in this bot, those calls end the turn without running. `context` points every tool at the mentioned issue ([Context](/context)).

## Install

:::code-group
```bash [pnpm]
pnpm add @github-tools/sdk @vercel/connect chat @chat-adapter/github @chat-adapter/state-memory workflow ai zod
```
```bash [npm]
npm install @github-tools/sdk @vercel/connect chat @chat-adapter/github @chat-adapter/state-memory workflow ai zod
```
```bash [yarn]
yarn add @github-tools/sdk @vercel/connect chat @chat-adapter/github @chat-adapter/state-memory workflow ai zod
```
```bash [bun]
bun add @github-tools/sdk @vercel/connect chat @chat-adapter/github @chat-adapter/state-memory workflow ai zod
```
:::

The Nitro and Vite config come with the example. Create a connector and pull its token as [Auth](/auth#create-a-github-connector) describes, then set the rest of `.env`:

```bash [.env]
GITHUB_CONNECT_CONNECTOR=github/my-connector
GITHUB_WEBHOOK_SECRET=
GITHUB_AGENT_USERNAME=triage-bot
```

In the repository's **Settings** > **Webhooks**, point a webhook at `/webhooks/github` with content type `application/json`, the same secret, and the **Issue comments** event. Use a different GitHub account for the bot than the one commenting: Chat SDK ignores the bot's own messages.

## Run it

:::code-group
```bash [pnpm]
pnpm dev
```
```bash [npm]
npm run dev
```
```bash [yarn]
yarn dev
```
```bash [bun]
bun run dev
```
:::

Expose port 3000 with a tunnel such as `cloudflared tunnel --url http://localhost:3000`, update the webhook URL, and comment `@triage-bot triage this` on an issue.

## Go further

Add `@chat-adapter/slack` to the adapters in `lib/agent.ts` to triage from a Slack channel with the same handlers. [Chat SDK](/integrations/chat-sdk) covers adapters and production state.
