Run the script with a repository and it prints draft release notes for everything merged since the latest release, grouped into features, fixes and other changes, ready to paste into a GitHub release. It reads only: the one write in its preset, `createRelease`, can't run because nothing in the script answers an approval.

## Files

```text
release-notes/
├── package.json                       # "type": "module", "generate" script
├── .env                               # VERCEL_OIDC_TOKEN
└── scripts/
    └── generate-release-notes.ts      # the whole agent
```

```ts [scripts/generate-release-notes.ts]
import { connectGithubTools } from '@github-tools/sdk/connect'
import { generateText, stepCountIs } from 'ai'

const [owner, repo] = process.argv.slice(2)
if (!owner || !repo) {
  console.error('Usage: tsx scripts/generate-release-notes.ts <owner> <repo>')
  process.exit(1)
}

const { text } = await generateText({
  model: 'anthropic/claude-opus-5.5',
  tools: connectGithubTools('github/my-connector', {
    preset: 'release-manager',
    context: { owner, repo },
  }),
  stopWhen: stepCountIs(10),
  prompt: `
    Find what changed since the latest release, or since the previous tag if there is no release.
    Draft release notes grouped into "Features", "Fixes" and "Other", one bullet per pull request,
    each linking its number. Do not create the release. Print the draft only.
  `,
})

console.log(text)
```

`connectGithubTools` builds the same tools as `createGithubTools`, with a token minted by a Vercel Connect connector and scoped to the preset. `context` fills in `owner` and `repo` on every call, so the prompt doesn't repeat them ([Context](/context)). `generateText` stops after one step unless you set `stopWhen`, so `stepCountIs(10)` lets the model read, then write the draft.

The `release-manager` [preset](/presets) has `getReleaseContext`, which returns the latest release, the one before it and the comparison between their tags in one call, plus `compareCommits` and `listPullRequests` for the details.

```json [package.json]
{
  "type": "module",
  "scripts": {
    "generate": "tsx --env-file=.env scripts/generate-release-notes.ts"
  }
}
```

## Install

:::code-group
```bash [pnpm]
pnpm add @github-tools/sdk @vercel/connect ai zod
pnpm add -D tsx
```
```bash [npm]
npm install @github-tools/sdk @vercel/connect ai zod
npm install -D tsx
```
```bash [yarn]
yarn add @github-tools/sdk @vercel/connect ai zod
yarn add -D tsx
```
```bash [bun]
bun add @github-tools/sdk @vercel/connect ai zod
bun add -d tsx
```
:::

Create a connector named `github/my-connector` and pull its token as [Auth](/auth#create-a-github-connector) describes, or swap `connectGithubTools` for `createGithubTools` with `GITHUB_TOKEN` set.

## Run it

:::code-group
```bash [pnpm]
pnpm generate vercel-labs github-tools
```
```bash [npm]
npm run generate vercel-labs github-tools
```
```bash [yarn]
yarn generate vercel-labs github-tools
```
```bash [bun]
bun run generate vercel-labs github-tools
```
:::

The draft prints to the terminal. Nothing is posted to GitHub.

## Go further

To publish the release too, move the prompt to [`createGithubAgent`](/integrations/ai-sdk) and answer the `createRelease` approval request once someone has read the draft, as in the [quick start](/start/quick-start#_3-approve-the-write).
