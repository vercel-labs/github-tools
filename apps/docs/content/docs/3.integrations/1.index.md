The same 91 tools, presets and approval rules ship through five entry points. Each one adapts them to how its framework calls tools, pauses for a person and keeps state.

| Integration | Import | What you get | Pick it when |
| --- | --- | --- | --- |
| [AI SDK](/integrations/ai-sdk) | `@github-tools/sdk` | A `ToolSet` for `generateText` and `streamText`, and `createGithubAgent`, a `ToolLoopAgent` | You already call the AI SDK, or want the smallest setup |
| [eve](/integrations/eve) | `@github-tools/eve-extension` | A mounted extension: tools, instructions and approval from one file | You build an eve agent |
| [TanStack AI](/integrations/tanstack-ai) | `@github-tools/sdk/tanstack` | Native TanStack server tools, a prebuilt agent and an approval middleware | Your app runs on TanStack AI's `chat()` |
| [Vercel Workflow](/integrations/workflow) | `@github-tools/sdk/workflow` | `createDurableGithubAgent`, where every model call and tool call is a workflow step | A run must survive restarts, or wait hours for an approval |
| [Chat SDK](/integrations/chat-sdk) | `@github-tools/sdk` with `chat` | A bot that answers @mentions on GitHub, Slack or Discord | People talk to the agent in a thread, not in your own UI |

Start from the runtime you already have. On eve, mount the extension: it handles approval, sign-in and durability for you. Otherwise start with the AI SDK entry point: Vercel Workflow and Chat SDK build on it, so its page explains the parts they share. Add Vercel Workflow when an in-process agent loses work on timeouts, and Chat SDK when the agent should live in a GitHub or Slack thread.

Agents that import `createGithubTools` from `@github-tools/sdk/eve` into `agent/tools/` use the deprecated direct import. [Upgrade](/reference/upgrade) moves them to the extension.
