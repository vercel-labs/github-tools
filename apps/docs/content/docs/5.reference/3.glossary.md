Every page uses these words with the meaning below.

| Term | Meaning |
| --- | --- |
| Tool | One GitHub operation the model can call, such as `listIssues`. An AI SDK `Tool` with a Zod input schema. See [Tools](/tools) |
| Read tool | A tool that doesn't change anything on GitHub. Never asks for approval |
| Write tool | A tool that changes something on GitHub. 45 of the 91 tools. Asks for approval by default |
| Context tool | A read tool that gathers what one task needs in a single call, such as `getPullRequestContext`. See [Context](/context#context-tools) |
| Preset | A named list of tools for one job, such as `code-review`, with a matching system prompt. See [Presets](/presets) |
| Core read tools | The five reads every preset includes: `getRepository`, `getFileContent`, `getRepositoryTree`, `searchCode`, `listCommits` |
| Approval | The pause before a write tool runs, until someone answers yes or no. See [Approval](/approval) |
| Approval request | What the agent returns instead of running a write tool: the tool name, its input, and an `approvalId` to answer |
| Decision model | The fast model behind every `'auto'` option. Jev by default |
| `'auto'` | Hand a choice to the decision model: `requireApproval: 'auto'` approves routine writes, `preset: 'auto'` picks the tools |
| `callGithubTool` | The tool an agent with `preset: 'auto'` uses to reach a GitHub tool outside its selection |
| Working context | Default `owner`, `repo`, pull request or issue number for a tool set. See [Context](/context) |
| Override | A per-tool change to the description, title or `needsApproval`, without changing what the tool does. See [Tools](/tools#overrides) |
| Paged list | A list result with `items`, `hasMore`, `page`, `perPage` and `nextPage` |
| Connector | A Vercel Connect connection to a GitHub App, which mints short-lived tokens for your deployment. See [Auth](/auth#vercel-connect) |
| Installation token | A token that acts as the GitHub App. What a connector mints by default |
| User token | A token that acts as one GitHub user who authorized the app. What a connector mints with a `subject` |
| Durable agent | An agent whose model calls and tool calls run as workflow steps, so it resumes after a crash. See [Vercel Workflow](/integrations/workflow) |
| Step | One retryable unit of a workflow. Every tool call runs in its own step |
| eve extension | `@github-tools/eve-extension`, which mounts the tools in an eve agent from one file. See [eve](/integrations/eve) |
