Build an eve agent that finds stale GitHub issues, comments to ask for an update, and closes them if nothing comes back.

- Mount @github-tools/eve-extension under agent/extensions/github.ts with preset: 'issue-triage' and a Vercel Connect connector
- Set requireApproval so addIssueComment is unattended but closeIssue always asks a human
- Use examples/eve-extension-agent as the project layout reference

::

A maintainer agent that runs on a schedule, finds issues with no activity in 30 days, posts a comment asking the author for an update, and closes the ones that get no response. Built on the [eve extension](/frameworks/eve-extension) with the `issue-triage` [preset](/guide/presets) and a [Vercel Connect](/guide/vercel-connect) connector for the token.

## Files

::code-group
```md [agent/instructions.md]
You are a maintenance agent for this repository. Your only job is triaging stale issues.

When asked to sweep for stale issues:
- Use listIssues to find open issues with no activity in the last 30 days
- Post one comment per stale issue asking the author to confirm it's still relevant
- If an issue already has a "stale" label and still has no response, close it with a short, polite explanation
- Never close an issue that has had any comment or label change in the last 30 days
- Report a short summary of what you did at the end
```

```ts [agent/agent.ts]
import { defineAgent } from 'eve'

export default defineAgent({
  model: 'anthropic/claude-sonnet-5',
})
```

```ts [agent/extensions/github.ts]
import githubExtension from '@github-tools/eve-extension'

export default githubExtension({
  connector: 'github/my-connector',
  preset: 'issue-triage',
  requireApproval: {
    addIssueComment: false, // low-risk, let the agent nudge authors unattended
    closeIssue: true, // always ask before actually closing something
  },
})
```
::

```bash [.env]
# Vercel Connect OIDC token, required by the "github/my-connector" connector.
# From this directory: vercel link && vercel env pull
VERCEL_OIDC_TOKEN=
```

## Set up the connector

::steps{level="3"}
### Create a GitHub connector

Create a connector named `github/my-connector` from the [Vercel dashboard](https://vercel.com/docs/connect), then install it on the org or repos this agent should triage. Full checklist: [Vercel Connect](/guide/vercel-connect#setup-checklist).

### Pull a local OIDC token

```bash [Terminal]
vercel link
vercel env pull
```

This writes `VERCEL_OIDC_TOKEN` into `.env`. Re-run `vercel env pull` when it expires.
::

## Run it

```bash [Terminal]
npx eve dev
```

Ask it to "sweep for stale issues on my-org/my-repo". It reads the issue list, comments on anything inactive, and asks for approval before closing.

::note
Swap `connector` for `token: process.env.GITHUB_TOKEN` if you'd rather manage a PAT directly, see [Tokens & Auth](/guide/tokens-and-auth#create-a-fine-grained-token) for the required scopes for `issue-triage`.
::

## Schedule it

To run this sweep automatically instead of on demand, add an eve [schedule](https://eve.dev/docs/schedules) that triggers the same prompt on a cron. See the bundled `node_modules/eve/docs/schedules.mdx` for the schedule file format.
