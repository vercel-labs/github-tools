Add the attribution footer to pull requests that `editFiles` opens, and let `attribution.footer` take a template.

With `attribution` on, a call that ran with a person's token added the footer only to `createPullRequest`. A pull request opened by `editFiles` with `pullRequest` got no footer, even though its description tells the model to prefer it over `createPullRequest`. It now gets the footer too.

The default footer now names the App by its display name, the person, and where they asked from:

> Generated by [Evi](https://github.com/apps/evlogai) for @HugoRCD from a [Slack thread](https://app.slack.com/client/…).

It was `Generated by [evlogai](https://github.com/apps/evlogai).`. Naming the person costs one `GET /user` call per pull request.

`attribution.footer` also accepts a template whose tokens the extension fills from each call: `{app}` (the App as a link), `{app.name}` (its display name), `{requester}` (`@<login>`), `{channel}` (such as `Slack` or `Linear`) and `{origin}` (a link to the Slack thread, the Linear issue by name, or the channel's name). An unknown token fails when the extension mounts. A function that gets the App and returns the line also works.

```ts
export default githubExtension({
  connector: 'github/my-connector',
  actAs: 'caller',
  attribution: { footer: 'Opened by {app.name} in {channel} for {requester}.' },
})
```

`@github-tools/sdk/eve-runtime` exports `fillGithubFooter`, `githubFooterTokens`, `githubAppFooterValues`, `githubChannelFooterValues`, `githubLogin`, `GITHUB_FOOTER_TOKENS` and `DEFAULT_GITHUB_FOOTER`, `GithubAppBot` gains `name`, and `withGithubAppFooter(body, bot, footer?)` takes the filled line as an optional third argument.
